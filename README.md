# mod-item-affixes (Conquest of Azeroth)

Random stat affixes on gear for the Conquest of Azeroth AzerothCore fork. Branch `coa` of
[Kainodyn/mod-item-affixes](https://github.com/Kainodyn/mod-item-affixes), adapted from Nevaden's
module: stat affixes rolled automatically for the receiver's CoA specialization, plus CoA class
skill affixes (spell modifiers on one class ability). Upstream's spellmod, spell-swap, talent, gem
and Imprint affixes, Player Progression, the manual roll UI, client DBC/MPQ patching and every core
patch are removed. Plans and decisions: [COA_PLAN.md](COA_PLAN.md) and
[COA_SKILL_AFFIX_PLAN.md](COA_SKILL_AFFIX_PLAN.md).

## How it works

- **Rolling.** A green, blue, epic or legendary weapon or armor piece rolls its affixes the moment a
  player receives it (loot, quest reward, crafting, vendor). An eligible item that never rolled
  (mail, auction, trade, gear from before the module) rolls for the wearer when first equipped or at
  login while equipped (`ItemAffixes.RollUnrolledOnEquip`). Rolled items keep their affixes through
  bank, mail and trade. Playerbots never roll or apply affixes.
- **Slots.** Green 1, blue 2, epic 3, legendary 4; two-handers +1 slot and 1.5x values. Shirts,
  tabards, bags, ammo, heirlooms and level-scaled items never roll.
- **Values.** `budget(iLvl) * slot modifier * quality fraction * StatMultiplier`, with the item level
  capped at `MaxBudgetItemLevel` (100) so test and custom items do not roll WotLK-sized values. A
  crit roll (10 %) gives 1.5x and shows in gold. An item does not repeat a stat while another fits.
- **Specialization.** Roles and primary attributes come from `ChrSpecs.dbc` (role flags and
  PrimaryStats) plus CoA's curated tank/healer lists. CoA classes use their active specialization;
  the original classes map their dominant talent tree onto ChrSpecs 64-93; Hero (Wildcard) may roll
  everything. Without a specialization only universal affixes roll.
- **Stats applied.** Through the core's own item stat lifecycle (`OnPlayerAfterApplyItemMods`):
  equip, unequip, destroy, durability 0 and repair, plus a full sync at login.
- **Reforge.** `/reforge`, or the Reforge Master (entry 601107, spawn with `.npc add 601107`): pay
  gold to reroll one line. The current value is always offered first; the item locks to that line.

## Class skill affixes (`data/sql/db-world/mod_item_affixes_template_skill.sql`)

Generated by `tools/skill_affixes/merge_reviews.py` from the reviewed lists (`SKILL_AFFIXES.md`):
707 affixes for the CoA classes 12-32, e.g. `Glacial Tap: -1.5 sec cooldown`.

- **Rolling.** Blue+ items of a CoA-class receiver: `SkillAffixChance` (20 %) for one skill affix in
  the first new line, weighted among the class's affixes (all specializations) whose `min_quality`
  the item meets and whose spell (`known_spell`, any rank) the receiver knows. At most one per item.
  A crit roll stores 150 in `rolled_value` (percent of the template values) when `scales_with_crit`.
  Reforge uses the same filter; a skill line only reforges into skill affixes.
- **Applying.** Same lifecycle as stats. One hidden passive carrier aura (spell 9979001, `spell_dbc`)
  owns every `SpellModifier` the module adds; the module deletes them and removes them before the
  aura goes (logout, `RemoveAllAuras`, `.unaura`; the carrier is restored 0.5 s later). Values of the
  same spell/op/type are summed over all items without a cap; summed cooldown, cast time and cost
  cuts are clipped so they never go below zero.
- **Targeting.** Every affix is a modifier on the carrier (family 0, mask 0) with `targetSpellId` on each
  `affix_skill_target` spell and every other rank of it (`spell_ranks`); cooldown affixes are
  `SPELLMOD_COOLDOWN` like any other op. The core sends the client no spellmod packet for these.
  `affix_template.targeting` and `mask0..2` are legacy columns (still written by the generator) that the
  module ignores; the former mask spellmods and `hook_cd` cooldown cuts (`OnSpellCast` +
  `ModifySpellCooldown`) were removed 2026-11-24.
- **Streamed Spell rows** (the only mode since 2026-11-24, client test A/B passed; needs the local core
  patch `core-ascension-spell-row-api.patch` and `CoA.SendDisplayPatches = 1`). After every rebuild the
  player gets a modified Spell row (`SMSG_PATCH_SPELL`) per affected spell:
  `RecoveryTime`/`CategoryRecoveryTime`, `ManaCost`(`Percentage`), `EffectBasePoints`, `EffectChainTarget`
  directly; `CastingTimeIndex`/`DurationIndex`/`EffectRadiusIndex` to the nearest existing row and
  `RangeIndex` to the longest row not above the server range; other effects as a green `Affixes: ...` line in
  the description. Original rows go out when an affix goes, 5 s after login and after a spec change. The
  client applies each affix once, through the row, so tooltip/action bar match the server effect. The
  module registers the core's row override, so core notice/swap rows of the same spell keep the affix
  values. The old `ItemAffixes.SkillAffixes.StreamSpellRows` key is ignored with a startup warning.
  Debug: `.affix skills` (mods and rows per spell), `.affix row <spell> ...` (send a test row).
  Plan and client test: `COA_SKILL_TOOLTIP_PLAN.md`.
- **Tooltip.** `<Spell>: <effect>`; grey `(inactive)` when the wearer does not know the spell.
- **Ids** are stable (`tools/skill_affixes/affix_ids.json`, `100000 + class_id * 1000 + n`).
  Removed affixes keep their id; existing item lines with them simply stop applying.
- `mod_item_affixes_template.sql` recreates `affix_template`: if it ever changes, re-apply the skill
  file as well (delete its `updates` row). Without the skill columns the module runs stat-only.

## Affix pool (`data/sql/db-world/mod_item_affixes_template.sql`)

| Affix | Who | Notes |
|---|---|---|
| Stamina, Crit, Haste, Hit Rating | everyone | Ratings apply to melee, ranged and spell. |
| Strength, Agility, Intellect, Spirit | spec's primary stats | Main stat full weight, other listed attributes (and Spirit for healers) `SecondaryAttributeWeightPct`. |
| Spell Power | caster, healer | blue+ |
| Mp5 | caster, healer with mana | |
| Attack Power, Expertise | physical (melee/tank) | blue+ |
| Ranged Attack Power | physical ranged | blue+ |
| Armor | tank, armor slots | |
| Dodge, Defense, Parry Rating | tank | blue+ |

Removed for CoA: Hp5, Armor Penetration, Move Speed, Damage Reduction, pet affixes.

## Install

1. Clone into `modules/mod-item-affixes` (branch `coa`), re-run CMake and build the worldserver.
2. Copy `conf/mod_item_affixes.conf.dist` to the worldserver's module config directory.
3. The DB updater applies `data/sql` to the world DB and to each realm's characters DB.
4. Players install `addon/ItemAffixes` (required for tooltips) and optionally
   `addon/ItemAffixesToast` in `Interface/AddOns`.

Startup log: `mod-item-affixes: loaded N specialization role profile(s) from ChrSpecs.dbc.`,
`mod-item-affixes: loaded N affix template(s).` and `mod-item-affixes: loaded N skill affix(es) ...`.

## GM commands

| Command | Effect |
|---|---|
| `.affix info` (GM) | Affixes of every equipped item. |
| `.affix spec` (GM) | The specialization profile (spec id, roles, primary stats) new rolls use. |
| `.affix skills` (GM) | Active skill affixes, their spell modifiers, cooldown cuts and streamed rows. |
| `.affix reforge status <equipSlot>` (GM) | Reforge state and next cost. |
| `.affix reroll <equipSlot>` (admin) | Replace every affix of an equipped item (1-based slot, see `.affix info`). |
| `.affix give <equipSlot> <id\|key> [crit]` (admin) | Put one skill affix on an equipped item (testing: no class/spell check). |
| `.affix row <spellId> [field=value ...] [desc="..."] [desc+="..."] [tooltip="..."]` (admin) | Send yourself an edited Spell row (client test; core patch needed). Fields: `RecoveryTime`, `CategoryRecoveryTime`, `ManaCost`, `ManaCostPercentage`, `EffectBasePoints0-2`, `EffectChainTarget0-2`, `CastingTimeIndex`, `RangeIndex`, `DurationIndex`, `EffectRadiusIndex0-2`, or `fieldN` (Spell.dbc column N). |
| `.affix row <spellId> reset` (admin) | Send the row the server normally sends (original, plus streamed affixes when on). |
| `.affix reforge roll/pick` (admin) | Reforge an equipped item without the addon. |

## Addon protocol

Prefix `AFXM`, whispered to the player themself; the server clears the request text so it never
echoes back (no core patch needed). Requests: `CONFIG`, `ALLDATA`, `DATA|bag|slot`, `PEEK|uid`,
`PEEKUNIT|name|slot`, `PEEKUNITALL|name`, `PEEKAUCTION|...`, `TRADEPEEK|slot`, `MYTRADEPEEK|slot`,
`REFORGE_STATUS/ROLL/PICK/PREVIEW|bag|slot|...`. Inspect lookups only answer for players within
100 yards in the same map; the auction lookup only accepts valid, escaped character names.
